# Tec-flow — Plan de Comunicación

## Canales

| Canal | Uso |
|-------|-----|
| Repositorio GitHub | Fuente única de verdad: código, documentación, issues, avances |
| Revisión semanal con el docente | Aprobación de hitos de fase |
| Registro en `docs/` | Decisiones técnicas y cambios de alcance |

## Cadencia

| Actividad | Frecuencia |
|-----------|------------|
| Commit y push de avances | Cada sesión de trabajo (al menos 2–3 por semana) |
| Revisión de avance con el docente | Semanal |
| Actualización de estado de fases en `README.md` | Al cerrar cada fase |

## Reglas de trabajo con el repositorio

1. Todo cambio relevante se commitea con mensaje claro (convención de Git).
2. La rama `main` siempre contiene la versión aprobada y funcional.
3. Las decisiones que alteran alcance, cronograma o riesgos se documentan antes de implementarse.

## Reporte de avance (plantilla)

- ¿Qué se hizo esta semana?
- ¿Qué se hará la próxima semana?
- ¿Hay bloqueos o riesgos activos?
- ¿Se requiere aprobación del docente para algo?
